# Tab Garden Tab Board Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Deliver a draggable, synchronized, sticky-note-like tab board in an extension tab.

**Architecture:** Pure board segmentation, composite-block geometry, virtual assignments, and deterministic masonry placement live in `shared.ts`. The service worker owns state and Supabase and queries tabs only; the board page only renders typed state and emits typed drag commands. Durable board group and layout metadata use stable keys and RLS-protected Supabase tables; no native Chrome tab-group APIs are used.

**Tech Stack:** Native strict TypeScript, Chrome/Edge MV3, Chrome tabs/tabGroups/storage APIs, Supabase PostgREST, HTML drag events, Node.js test runner.
